## 3. Signal Reference Guide

Generic ophyd signal semantics — applies to every signal listed above.

### 3.1 Resolving a full PV address

For any signal, the full EPICS PV is `{device.prefix}` + `{component.suffix}`. Example: `bss` has prefix `usxTerms:bss:`. Component `esaf` is a sub-device with suffix `esaf:`; its component `number` has suffix `id`. So the full PV is `usxTerms:bss:esaf:id`.

### 3.2 `kind` semantics

| Kind | Meaning |
|------|---------|
| `normal` | Primary data signal. Included in `device.read()` and the primary data stream. |
| `config` | Configuration signal. Included in `device.read_configuration()` — recorded as run metadata, not in the primary data stream. |
| `omitted` | Operational/internal signal. Not in `read()` or `read_configuration()`. Must be accessed explicitly via `.get()` / `.put()`. |
| `hinted` | Like `normal`, plus marked as a primary plotting axis. |
| *(unset)* | Defaults to `normal` (per ophyd). |

### 3.3 Reading and writing signals (interactive / IPython equivalent)

```python
# Read a signal value (returns the current value)
value = device.signal_attr.get()

# Read a string-valued signal (string=True in the class definition)
status = device.string_signal.get()

# Write a value (returns immediately for EpicsSignal)
device.signal_attr.put(new_value)

# Write and wait for callback completion
device.signal_attr.set(new_value).wait()
```

For an `EpicsMotor` (and `TunableEpicsMotor2`):

```python
device.position                      # current readback (float)
device.move(target, wait=True)       # blocking absolute move
device.user_setpoint.put(target)     # non-blocking — set setpoint only
device.user_readback.get()           # live readback
```

### 3.4 Read-only signals

`EpicsSignalRO` (and any signal with `write_access=False`) cannot accept `.put()`. Calls to `.put()` will raise `ReadOnlyError`.

### 3.5 String signals

When a component is declared with `string=True`, `.get()` returns a Python `str` rather than the underlying numeric enum value. Use the string form when matching against documented enum values.

### 3.6 Sub-device access

Components whose signal class is itself a `Device` subclass are marked with ⤵ in the §2 tables. Access them by attribute chaining:

```python
device.subdevice_attr.signal_on_subdevice.get()
```

Each level prepends its prefix to form the final PV.
