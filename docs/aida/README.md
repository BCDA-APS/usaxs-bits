# AIda orientation docs

AIda is an AI agent that operates the USAXS / SAXS / WAXS instrument at
APS 12-ID-E through the bluesky-queueserver MCP tools, plus some direct
EPICS/ophyd tools. It runs in its own harness and typically does **not**
have good access to this repository's source, so it can't read
`src/usaxs/startup.py` or the top-level `SKILL.md` (that file is written for
a coding agent that edits plan files in place, not an agent operating the
live queue server).

These four files are plain-Markdown reference material meant to be fed to
AIda as context (pasted into a system prompt, loaded as retrieval chunks,
attached as files — whatever AIda's harness supports). Nothing in this repo
loads them automatically. Read them in this order:

1. **[01-terminology.md](01-terminology.md)** — glossary of USAXS/SAXS/WAXS
   technique and instrument vocabulary, plus core Bluesky/ophyd/queueserver
   concepts, for a reader who doesn't already know this beamline.
2. **[02-plans-catalog.md](02-plans-catalog.md)** — the plans AIda can
   actually submit to the queue server (a narrower list than the full
   `src/usaxs/plans/` surface), with parameters and when to use each.
3. **[03-devices-and-pvs.md](03-devices-and-pvs.md)** — how to resolve a
   device request to a PV, and the devices AIda is most likely to touch
   directly.
4. **[04-safety-and-escalation.md](04-safety-and-escalation.md)** — what
   AIda must not do autonomously and when to stop and ask a human. Mostly
   placeholders — beamline policy that only beamline staff can fill in.

## Keeping these in sync

This is hand-written material and will drift, like any doc. Revisit it when:

- `src/usaxs/startup.py`'s `if running_in_queueserver(): ...` import block
  changes (adds/removes a plan) — update
  [02-plans-catalog.md](02-plans-catalog.md).
- `src/usaxs/configs/*.yml` gains, loses, or renames a device — update
  [03-devices-and-pvs.md](03-devices-and-pvs.md) and check
  [`../../device_skills_*.md`](../../device_skills_20260429_115332.md) (the
  repo-root device catalog) for the same gap.
- `src/usaxs/qserver/user_group_permissions.yaml` changes what a group can
  call — update the permissions note in
  [02-plans-catalog.md](02-plans-catalog.md).

The most reliable ground truth for "what plans/devices exist right now" is
always `src/usaxs/qserver/existing_plans_and_devices.yaml` — it's
regenerated by the queue server itself, not hand-maintained. When any of
these docs and that file disagree, trust the file.
