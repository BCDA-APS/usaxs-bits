# Devices and PVs — resolving a request to hardware

## How to look up a device

1. **Start with [`device_skills_*.md`](../../device_skills_20260429_115332.md)**
   at the repo root — a full catalog of every instantiated device, its
   class, and every component signal down to the PV. Section 1 is a flat
   table of every device instance; Section 5 is a quick-lookup summary;
   Section 2 has one numbered subsection (`§2.N`) per device class with the
   full attribute/PV table. Start at Section 5, drill into the `§2.N`
   section it points to for full detail.
2. **If it looks stale or you can't find something**, check
   `src/usaxs/qserver/existing_plans_and_devices.yaml`'s `existing_devices:`
   block instead — it's regenerated by the queue server itself, so it's
   always current, though it's YAML (machine-shaped, not prose) and doesn't
   explain *purpose*, only structure (`classname`, `module`, `components`,
   `is_readable`/`is_movable`/`is_flyable`).
3. Device names are what you address in the queue server — never construct
   a PV path yourself when a named device already exists for it.

## Labels

Devices in `src/usaxs/configs/*.yml` carry `labels:` such as `baseline`,
`shutters`, or a stage-specific tag. `baseline` devices are read
automatically at the start and end of every run for provenance — you never
need to request that yourself. Other labels are mostly organizational
(e.g. grouping all shutters) rather than something that changes plan
behavior.

## Operation vs. simulation shutters

At session start, `startup.py` checks the live PV
`usxLAX:blCalc:userCalc2.VAL`. A value of `1` loads real PSS shutter classes
(`shutters_op.yml`); anything else loads simulated shutter devices
(`shutters_sim.yml`). The device names (`FE_shutter`, `mono_shutter`,
`usaxs_shutter`, `a_shutter_autoopen`) are identical either way — only the
underlying class/PVs differ. This is decided once per queue-server
environment start, not per plan, so if shutter behavior seems wrong, the
likely cause is which mode the environment started in, not the plan you
just ran.
