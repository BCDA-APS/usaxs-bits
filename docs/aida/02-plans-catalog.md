# Plans catalog — what AIda can submit to the queue server

`src/usaxs/startup.py` imports a **different, smaller** set of plans when
running under the queue server (`if running_in_queueserver(): ...`) than it
does for an interactive console session. AIda operates through the queue
server, so **this file's list — not the full `src/usaxs/plans/` directory —
is what's actually callable.** It was built from that import block and
cross-checked against the live `existing_plans:` block of
`src/usaxs/qserver/existing_plans_and_devices.yaml` (regenerated by the
queue server itself — re-derive this table from that file if they ever
disagree).

All of these are Bluesky **plans**: submit them to the queue as items, don't
expect a return value back inline — read results from the resulting run's
data/metadata after it completes.

## Data collection

| Plan | Parameters | Purpose |
|---|---|---|
| `USAXSscan(x, y, thickness_mm, title, md=None)` | position (mm), position (mm), sample thickness (mm), scan title string | Collect a USAXS measurement at one sample position. Dispatches to fly-scan or step-scan automatically based on the instrument's `terms.FlyScan.use_flyscan` setting. **Use this**, not `Flyscan`/`USAXSscanStep`, unless you specifically need to force one mode. |
| `Flyscan(pos_X, pos_Y, thickness, scan_title, md=None)` | same shape as above, note the different parameter names | Force a fly-scan USAXS measurement. |
| `USAXSscanStep(pos_X, pos_Y, thickness, scan_title, md=None)` | same shape as `Flyscan` | Force a step-scan USAXS measurement (slower; a fallback when fly-scan hardware/alignment is unavailable). |
| `saxsExp(pos_X, pos_Y, thickness, scan_title, md=None)` | position (mm), position (mm), thickness (mm), title | Collect one SAXS image at a sample position. |
| `waxsExp(pos_X, pos_Y, thickness, scan_title, md=None)` | same as `saxsExp` | Collect one WAXS image at a sample position. |

A full "USAXS/SAXS/WAXS set" is these three run back-to-back at the same
position — see [01-terminology.md](01-terminology.md). `USAXSscan`,
`saxsExp`, and `waxsExp` are the three plans wrapped with beam suspenders
(`suspend_FE_shutter`, `suspend_BeamInHutch`) in `startup.py`: they pause
automatically on a shutter close or beam-in-hutch drop and resume when
clear. The other plans below are **not** suspender-protected.

## Mode changes

Move the instrument's optics/detectors into a physical configuration; they
don't collect data themselves. Data-collection plans switch mode internally
as needed, so you don't need to call these first before `USAXSscan`/
`saxsExp`/`waxsExp`.

| Plan | Parameters | Purpose |
|---|---|---|
| `mode_USAXS(md=None)` | metadata only | Configure for USAXS. |
| `mode_SAXS(md=None)` | metadata only | Configure for SAXS. |
| `mode_WAXS(md=None)` | metadata only | Configure for WAXS. |
| `mode_Radiography(md=None)` | metadata only | Configure for USAXS radiography (transmission imaging). |
| `mode_DirectBeam(md=None)` | metadata only | Configure for direct-beam Blackfly imaging. |
| `mode_OpenBeamPath(md=None)` | metadata only | Move all components out of the beam path. |

## Tuning / alignment

Short scans that find and set a peak-intensity position on one axis — not
data collection. Run these when scattering intensity looks low or after a
mode change/long idle, per beamline practice

| Plan | Parameters | Purpose |
|---|---|---|
| `tune_ar(md=None)` | metadata only | Tune the analyzer rotation (AR) stage. |
| `tune_a2rp(md=None)` | metadata only | Tune the analyzer second roll-pitch piezo (A2RP). |
| `find_ar(md=None)` | metadata only | Wide-range AR search, then a fine `tune_ar`. Use when AR has drifted far enough that a plain tune won't find the peak. |
| `find_a2rp(md=None)` | metadata only | Wide-range A2RP search, then a fine `tune_a2rp`. |
| `tune_mr(md=None)` | metadata only | Tune the monochromator/collimator rotation (MR) stage. |
| `tune_dx(md=None)` | metadata only | Tune the detector X (DX) stage. |
| `tune_dy(md=None)` | metadata only | Tune the detector Y (DY) stage. |
| `tune_diode(md=None)` | metadata only | Tune both DX and DY together. |
| `tune_usaxs_optics(side=False, md=None)` | `side`: bool, use the side-reflection geometry variant | Run the full USAXS optics tune sequence (multiple axes in order). |
| `lineup2(detectors, mover, rel_start, rel_end, points, peak_factor=1.5, width_factor=0.8, feature='centroid', nscans=2, signal_stats=None, reporting=None, md={})` | generic apstools alignment plan | Lineup/center an arbitrary mover relative to its current position using a detector signal — a general-purpose alignment primitive, not USAXS-specific. Prefer the named `tune_*`/`find_*` plans above for the instrument's standard axes; reach for `lineup2` only for something they don't cover. |

## Session / housekeeping

| Plan | Parameters | Purpose |
|---|---|---|
| `new_user_plan(user, sample='data', scan_id=1, skip_bss=False)` | user name, sample dir name, starting scan id, whether to skip the beamline scheduling system lookup | Queueable wrapper around `newUser()`: sets up the monthly/user data directories, resets file numbering, configures file writers, logs a session-start note. Call at the start of a beamtime/session. |
| `new_sample_plan(sample)` | sample directory name | Queueable wrapper around `newSample()`: switches the active sample directory and logs a new-sample note. Requires `new_user_plan` to have run first in that session. |
| `reset_USAXS()` | none | Return the instrument to a known-safe configuration. Use after an abort or when state looks inconsistent. |
| `run_command_file(filename, md=None)` | path to a text or Excel command list | Execute a pre-written list of commands/plans from a file — the queue-server equivalent of running a full experiment script. |

## Functions available outside the plan queue

`src/usaxs/qserver/user_group_permissions.yaml` also allows two RE-Manager
**functions** (not plans — invoked via the queue server's function-execute
API rather than queued as a scan) for the `primary` group: `newUser` and
`newSample`, the same underlying calls that `new_user_plan`/`new_sample_plan`
wrap. It additionally lists `read_device` and `set_device` — these are
generic device-read/write primitives provided by the queue-server MCP
bridge itself (not defined in this repo), for reading or setting a signal
directly without going through a named plan.
